# Architecture

The app turns settings into a score and a score into a picture. Those two steps are kept apart, and the first one is kept free of the browser.

```
settings ──► generateScore(settings, seed) ──► Score ──► layoutScore(score, width) ──► coordinates ──► SVG
  state/           music/  (pure)                          render/layout.js (pure)       render/draw.js, score.js
```

`src/main.js` is the only module that knows about all of them. It loads the settings, picks a seed, asks for a score, and asks for it to be drawn. It redraws when a setting changes, when the view changes, and when the page width changes.

A Score can leave the page two ways, and both start from the Score itself, never from the picture:

```
Score ──► encodeScore ──► localStorage ──► decodeScore ──► Score          (the library)
Score ──► layoutScore(score, 960) ──► scoreToPdf ──► bytes ──► download   (the PDF)
```

## Modules

| Directory | Job | May use |
|---|---|---|
| `src/music/` | Decide which notes are in a study | Nothing outside itself |
| `src/state/` | Defaults, validation and storage of settings; the saved-studies library | `music/` for the lists of valid values and the score codec |
| `src/render/` | Geometry (`layout.js`), then drawing | `music/` for pitch and fretboard helpers |
| `src/export/` | The PDF: a second renderer, and the file download | `music/`, `render/glyphs.js`, `render/layout.js` |
| `src/ui/` | The settings panel, the library dialog and the words around the score | `music/`, `render/glyphs.js`, `render/svg.js` |
| `src/main.js` | Wiring | Everything |

Dependencies point one way: `music/` imports nothing from the other directories, and nothing imports `main.js`.

### `src/music/`

- `pitch.js` — the pitch model, spelling with sharps or flats, staff steps.
- `fretboard.js` — which pitches each position offers on which strings, with fingerings (`poolFor`).
- `rng.js` — the seeded generator (`mulberry32`) and `pick`, `weightedPick`, `shuffle`.
- `positions.js` — which position each measure is in.
- `rhythm.js` — beat cells and measure rhythms for both melody modes.
- `theory.js` — tonal centres, scale-degree weights and chord progressions for Musical mode.
- `random-melody.js`, `musical-melody.js` — the two melody generators.
- `generate.js` — the entry point that calls the others in order.
- `score-codec.js` — packs a Score into a small JSON-safe form and rebuilds it (`encodeScore`, `decodeScore`).

### `src/render/`

- `glyphs.js` — SMuFL code points and Bravura metrics.
- `layout.js` — accidentals in force, spacing, system breaks, stems and beams. Pure.
- `draw.js` — primitives that draw one thing each: staff, clef, time signature, note, beam, barline.
- `score.js`, `note-map.js` — the two views.
- `tooltip.js` — the fingering tooltip.

### `src/export/`

- `score-pdf.js` — `scoreToPdf(score, { text, pageSize })` returns the bytes of a PDF. It draws the output of `layoutScore` element for element, as `draw.js` does, so the two renderers must be changed together. Pure: it runs in Node, which is how it is tested.
- `pdf-writer.js` — a minimal PDF 1.4 writer: lines, polygons, reusable outlines and text in the built-in Times faces.
- `times-metrics.js` — the advance widths of those faces, for centring and right-aligning text.
- `glyph-outlines.js` — the outlines of the six Bravura glyphs the score uses. Generated by `scripts/extract-glyph-outlines.mjs`; never edited by hand.
- `download.js` — hands the bytes to the browser as a file, and chooses Letter or A4 from the reader's region. The only module here that touches the DOM.

### `src/ui/`

- `controls.js` — the settings panel.
- `describe.js` — every sentence about a study: title, the lines under it, plate number, library row, file name. Pure text, shared by the page, the library and the PDF so they cannot drift apart.
- `title-block.js` — writes those sentences into the page.
- `library-dialog.js` — the list of saved studies.

## Data

**Settings** (`src/state/settings.js`): `positions`, `rotatePositions`, `strings`, `noteValues`, `accidentals`, `melody`, plus two that the interface does not expose yet, `measures` and `maxLeapSteps`. `sanitize` turns any stored value into valid settings, and no list is ever empty.

**Score** (`src/music/generate.js`):

```js
{
  seed,                    // the study's number
  settings,                // a copy of the settings it was generated with
  tonality,                // "C major" and so on in Musical mode, null in Random mode
  measures: [{
    number,                // from 1
    position,              // 1-12
    notes: [{ pitch, start, dur }]   // start and dur in sixteenths within the measure
  }]
}
```

A **pitch** is `{ letter, octave, alter, value, fingerings }`. `value` is `octave * 12 + pitch class` of the written pitch. `fingerings` is a list of `{ string, fret, finger }`, already narrowed to the enabled strings.

**Saved study** (`src/state/library.js`, localStorage key `guitar-reading-assistant.library.v1`): a JSON array of `{ id, savedAt, data }`, where `data` is the encoded Score:

```js
{ v: 1, seed, tonality, settings, measures: [{ p: position, n: [[value, alter, dur], ...] }] }
```

The notes are stored, not just the seed, so a saved study still opens unchanged after the generators have been retuned. What can be worked out again is left out: a note's start, a measure's number, and each pitch's letter, octave and fingerings, which `decodeScore` takes from the fretboard. `decodeScore` returns `null` for anything it cannot read and never throws; entries it cannot read are left in storage untouched, so a newer version's studies survive an older one. A study in quarter notes takes about 1 KB.

**Layout** (`layoutScore`): systems, each with its staff position, its measures, and for every note its `x`, `y`, ledger lines, accidental sign and stem, plus the beams of each measure.

## Rules that hold everywhere

- A note's pitch always comes from the pool of its measure's position, so it always has a fingering there.
- A measure always lasts sixteen sixteenths, and no note crosses a beat.
- The same settings and seed always give the same Score.
- Layout never changes the music, and drawing never changes the layout.
- A saved or exported study is described by `score.settings`, the settings it was generated with, not by the settings panel.
- Storage is best-effort: the library and the settings never throw when localStorage is missing, blocked or full. They report it, and the app carries on.

## How a change usually travels

A new setting: `settings.js` (default and validation) → the control in `index.html` and `ui/controls.js` → the generator or renderer that reads it → a test → the relevant doc.

A new notation element (a rest, a tie): the Score shape in `generate.js` → the codec in `score-codec.js`, as a new version that still reads the old one → geometry in `layout.js` with a test → a primitive in `draw.js` and the same one in `export/score-pdf.js` → `docs/engraving.md`.
