# Guitar Reading Assistant

A browser app that generates sight-reading studies for classical guitar and engraves them as SVG. It is a static site: no build step, no runtime dependencies, no framework.

## Commands

- `npm start` — serve the app at http://localhost:5173. ES modules do not load from `file://`, so opening `index.html` directly does not work.
- `npm test` — run every unit test (Node's built-in runner; needs Node 22 or newer).
- `node --test test/musical-melody.test.js` — run one test file.
- `node --test --test-name-pattern="cadence" "test/*.test.js"` — run tests by name.

There is no lint, type-check or build command.

**Deployment:** GitHub Pages serves the root of the `main` branch at https://tonymichaelhead.github.io/guitar-reader-assistant/. Pushing to `main` publishes, usually within a couple of minutes. The empty `.nojekyll` file tells Pages to serve the files exactly as they are.

## Hard constraints

- **No dependencies, bundler, framework or TypeScript.** The browser loads the files in `src/` as they are. See `docs/decisions/0001`.
- **`src/music/` is pure.** No DOM, no `Math.random`, no clock. All randomness comes through the `rng` argument, so a seed reproduces a score. See `docs/decisions/0003`.
- **`src/render/layout.js` is pure too.** It turns a Score into coordinates. Only `svg.js`, `draw.js`, `score.js`, `note-map.js` and `tooltip.js` touch the DOM.
- **Notation is drawn by hand with Bravura glyphs.** Do not add a notation library. See `docs/decisions/0002`.
- **Fonts in `assets/fonts/` ship unmodified, with their licence texts.** Bravura and Playfair Display have Reserved Font Names: do not subset, convert or rename them.

## Where things are

- `src/music/generate.js` — the single entry point of the music core: `generateScore(settings, seed)` returns a Score. The Score shape is documented at the top of that file.
- `src/main.js` — the only place a seed is chosen, and the only module that connects settings, score and page.
- `src/state/settings.js` — every setting, its default and its validation. A new setting starts here.
- `src/render/glyphs.js` — every SMuFL code point and Bravura metric the renderer uses.
- `src/music/score-codec.js` and `src/state/library.js` — how a Score is packed for storage, and the saved-studies list in localStorage.
- `src/export/` — the PDF export. `score-pdf.js` is a second renderer: it draws the same `layoutScore` output as `src/render/draw.js`, into a PDF instead of SVG.
- `src/ui/describe.js` — every sentence shown about a study (title, lines under it, plate number). The page, the library and the PDF all take their wording from it.

Units, which are easy to get wrong:

- Durations are counted in sixteenths: quarter 4, eighth 2, sixteenth 1.
- A pitch `value` is `octave * 12 + pitch class` of the *written* pitch, so C4 is 48. Guitar music sounds an octave lower than written.
- Layout lengths are SVG units; `SPACE` (12) is one staff space. Write sizes as multiples of `SPACE`, not as bare numbers.

## Conventions

Generators take their inputs as one object and the `rng` last, and never reach for global state:

```js
export function randomMelody({ pools, rhythm, maxLeapSteps }, rng) {
  // ...
  choice = pick(rng, pool); // never Math.random()
}
```

- Comments say why, or state a musical or engraving rule; they do not restate the code.
- Tunable numbers of the musical generator live in the exported `TUNING` object, not inline.
- Controls are native inputs (`checkbox`, `radio`) styled with CSS. Do not rebuild them from `div`s.
- Colours, fonts and sizes come from the custom properties in `styles/tokens.css`.
- Commit messages are one short imperative sentence, like the existing history ("Add toggle for individual strings").

## Boundaries

**Always**

- Run `npm test` before calling a change done.
- Add or adjust a test with any change under `src/music/` or to `src/render/layout.js`.
- Look at the result in a browser (`npm start`) for anything visual. Tests cannot see the page.
- Update the doc that describes a behaviour in the same change that alters it.

**Ask first**

- Adding a dependency, a build step or a new top-level directory.
- Changing the Score shape, or a localStorage key or stored format (`settings.js`, `library.js`, `score-codec.js`). People's saved studies must keep opening: a format change needs a new codec version that still reads the old one. The same goes for removing a note from a position in `fretboard.js`: a stored study is checked against those pools when it is read.
- Changing what Random mode produces. It is deliberately the original algorithm.
- Replacing or adding fonts.

**Never**

- Call `Math.random` under `src/music/`, or touch the DOM there or in `layout.js`.
- Put a notation glyph or metric anywhere but `glyphs.js`.
- Edit `src/export/glyph-outlines.js` by hand. It is generated by `scripts/extract-glyph-outlines.mjs`.
- Weaken a test's threshold to make it pass without saying so.

## Gotchas

- Position I covers five frets (open strings plus frets 1–4). Every other position covers four.
- A pitch object carries its fingerings. To change a spelling use `respell`, which keeps them; `spell` makes a bare pitch.
- Musical mode is always given the full chromatic pool and decides for itself whether to use it. Random mode is given the pool already filtered by the accidentals setting.
- Only files matching `test/*.test.js` are tests. `test/helpers.js` is shared code.
- Settings persist in localStorage under `guitar-reading-assistant.settings.v1`. Remove that key to see the defaults again. Saved studies are under `guitar-reading-assistant.library.v1`.
- There are two renderers. A change to how something is drawn in `src/render/draw.js` or `score.js` almost always needs the same change in `src/export/score-pdf.js`, and the other way round.
- A saved study is described and exported from `score.settings`, the settings it was generated with, not from the settings panel, which may have changed since.
- Several musical-mode tests assert statistics over many seeds (share of steps, share of chromatic notes). If you retune `TUNING`, expect to revisit them and the figures quoted in `docs/music-generation.md`.
